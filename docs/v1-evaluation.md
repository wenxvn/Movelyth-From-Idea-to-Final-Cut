## 2.1 T01 真实模型尝试（进行中，未通过）

- 环境修复：本机 `%APPDATA%\npm` 的 `@openai/codex` 缺可选依赖，已在一个临时目录安装
  `@openai/codex@0.163.0`（含 `codex-win32-x64`）并通过 `MOVELYTH_CODEX` 指向它；
  后端需要代理（`HTTPS_PROXY=http://127.0.0.1:7897`）。此路径不写入仓库配置。
- `movelyth create "矩阵为什么能让整个空间旋转？" --plan-only` 成功：真实 Codex 研究
  （6 facts / 2 sources / 6 claims）+ 真实编导（long 9 镜 999 字、short 3 镜 237 字）+ 独立审稿通过。
- 完整制作过程中独立视觉审片连续拒绝，暴露出真实的质量问题并被逐个修掉：
  - 公式/矩阵排版过小、多行被压成一行 → 数学图层放大并保留换行；
  - `line` 形状只画了第一段 → 改为按全部顶点画折线，`connect` 时加起点圆点与箭头；
  - 不同图层占用同一区域互相遮挡 → 布局区域改为互不重叠，并在脚本审批阶段直接拒绝重叠；
  - 时间线/流程图文字过小 → 放大字号与节点框。
- 期间还修掉几个真实缺陷：
  - 视觉审稿拒绝时 `Finding` 对象不可 JSON 序列化；
  - 脚本被拒绝后 resume 会静默重新生成同样脚本（现在把拒绝原因写入 `script-feedback.json`，
    下次 resume 继续反馈，通过后清除）；
  - 缓存里的"已审脚本"在契约变更后仍会被复用并直接进渲染（现在把 `scenedsl/consistency/quality`
    的 hash 计入 script 阶段输入，且校验失败会转成可修复的编辑反馈重新生成）；
  - 一次输出整部 Film 会触发 `max_output_tokens`，改为 long/short **分两次生成**（`director_split`）。
- 真实成片结果：
  - **VID-000002（T01）通过**：横版 242.6 s / 1920×1080、竖版 64.8 s / 1080×1920，30 fps、
    H.264/AAC，11 项技术检查全部通过，独立视觉审片 `passed=true`、`issues` 为空，
    制作模式 `title-driven-codex-agents`，交付 13 个文件。
    保留 1 条非阻断 warning：l8 讲"插值中点塌缩"时 matrix 是全零矩阵，被提示"不是纯旋转"
    （旁白本身已说明"画面里这段演示只到中点"）。
  - **VID-000003（T02）通过**：横版 218.9 s、竖版 67.2 s，11 项技术检查全部通过，
    视觉审片 `passed=true`、`issues` 与 `script_warnings` 均为空。
    交付 13 个文件，含分层封装示意、TTL 柱状图（末值 0 正确显示为无柱）。
  - **VID-000004（T03）未完成**：已跑完研究/编导/配音/渲染，视觉审片连续指出可读性问题
    （深灰文字对比度、柱状图字号、流程图过小），逐项修复后 **Codex 额度再次用尽**
    （提示 11:21 后恢复），最终成片未产出。
- 由此得到 2 个通过的真实题材（数学变换、网络传输），第 3 个题材被额度阻塞。
