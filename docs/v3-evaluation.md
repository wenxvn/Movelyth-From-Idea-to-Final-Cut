# V3 对照评估：同一份脚本，从“专业画面”到“专业讲述”

日期：2026-10-27。对象：`main` + 本轮改动（未提交前的工作树）。
对照：V2 `VID-000015`（同一脚本、V2 渲染与声音）vs V3 `VID-000025`（同一脚本 + V3 导演字段）。
`VID-000022` / `VID-000023` / `VID-000024` / `VID-000025` 是同一套代码在修正版面细节后的连续重跑：
音频合成去重（`VID-000023`）指标逐项不变；`immersive` 顶部注改到标题列下方（`VID-000024`）；
单注左对齐（`VID-000025`）。最终数字取自 `VID-000025`。

## 0. 结论

- **画面**：主体高度中位数从画面 21% 提到 53%，空白网格从 44% 降到 27%（同一批代表帧、
  同一测量代码）。标题、标签、公式、Insight 卡形成左栏真正的信息层，图表占满主区域，
  注释点带数值与判断，不再只是“一根线两个标签”。
- **讲述**：长镜被真实字幕句切成 36 个 coverage beat（V2：0），每个 beat 换 Insight、
  换注释、轻推/轻拉镜头；镜头内的静止采样占比从 4.3% 降到 2.4%，帧间运动量 0.386 → 1.05。
- **声音**：音效从 9 个（2 种）增加到 41 个（10 种），10.7 个/分钟；句级韵律升级为
  “从句 + 重点词”两级，配乐按角色能量分段，音效与画面动作同锚点（自动事件同步率 68%，
  其余是有意的句首/章节标记）。混音/原声比 1.17（V2 1.20），响度 -14.3 LUFS。
- **未完成**：真实 Codex 编导（本机无 `codex`）；人工完整观看与实听。脚本层面的
  镜头时长均匀（8/9 镜 24–28 s）**没有被渲染器修好**，它需要真实编导遵守新 prompt。

| # | 缺陷 | 修法 |

## 4. 声音：能测的与不能测的

**能测**

- 旁白按“句 → 从句 → 重点短语”三级合成（`prosody: clause+emphasis`）。重点词单独放慢 10%、
  响 6%，从句之间 35–100 ms，句末按标点 120–420 ms。
- 41 个声音事件：8 类来源（导演 3、转场 7、动作起 8、动作末 5、句首 10、标记 1、结论 1、
  角色 6）。68% 的自动事件落在动作/转场/边界的 ±0.30 s 内，其余是有意的句首与章节标记。
- 配乐按镜头角色给能量（hook 0.72 / mechanism 0.56 / example 0.46 / turn 0.80 / conclusion 0.66），
  turn 段会掉一次脉冲；body 段才出琶音与打击。
- 所有音效走同一条合成混响总线（0.85 s、按 `sum|h|` 归一），另加 -66 dBFS 房间底噪，
  避免句间“数字静音”。
- 立体声：人声居中（两条相同），bed 用 6.7 ms 延迟做宽度，琶音与音效分侧；相关系数 0.997。
  报告里明确写“人声为主的混音接近 1 是正常的”，不把它当质量分。

**不能测**

音色是否自然、停顿是否在气口上、配乐是否好听、音效是否刺耳、重点句是否听得出来。
`quality.json` 里 `human_review.listened_audio` 仍是 `false`：我没有实听。

## 5. 仍然不够好

1. **镜头时长仍然均匀**：8/9 镜 24.1–28.1 s。这是脚本问题，渲染器无法把 25 s 的镜头“剪短”，
   只能让它内部有变化。新 prompt 要求铺垫 8–14 s、机制 18–28 s、结论 10–16 s，
   但**没有真实模型验证**。
2. **coverage 指标偏粗**：115 个字幕页、36 个 beat，±0.8 s 的判定窗口最多覆盖约 25–30%；
   覆盖率 47% 说明还有一半的句子只有“人声 + 轻推”，没有新的视觉锚点。要更高，必须让编导
   每句都给动作，或允许渲染器按句切镜头（会打断连续运镜，需另做设计）。
3. **静止指标仍会低估**：2 fps 中位数对“只有柔光呼吸”的镜头不敏感；`static_sample_share`
   2.6% 不代表“不呆板”，只代表画面在变。
4. **短版主体偏小**（0.244）：竖版两条 390 px 高的对照图，加上标题/字幕带，主体高度上限就低；
   若把两图改成一条“共用坐标轴”的双系列图会更好，但需要 DSL 支持并排子图或共享轴。
5. **转场仍是固定 0.55–0.66 s**：没有按内容（匹配剪辑、同元素承接）自适应。
6. **没有章节卡**：章节名只在镜号旁，跨镜头的“段落感”靠角色能量与转场，未做真正的章节卡。
7. **未做真实端到端**：新字段（chapter/role/takeaway/metric/hero/annotations）在真实模型上的
   采纳率未知；prompt 变长也可能增加修复轮次。

## 6. 复现

```powershell
# 1. 从 V2 对照脚本派生 V3 导演版（只加元数据）
.\.venv\Scripts\python.exe tools\ab\make_film_v3.py

# 2. 用对照配置跑流水线（mock 审片，交付到 delivery-ab/）
$env:MOVELYTH_CONFIG = "tools\ab\movelyth-ab.toml"
.\.venv\Scripts\python.exe -m movelyth create "梯度下降为什么能让模型逐步减少错误？" `
    --new --import-film workspace\ab\film-004-v3.json `
    --import-research workspace\VID-000004\research.json

# 3. 指标在 workspace\VID-xxxxxx\quality.json 的 composition / rhythm / pacing / sound_design
# 4. 指定帧对照：tools\ab\frame_spec.py + studio\render-frames.mjs
```

`tools/ab/README.md` 记录了每个脚本的用途。`render-frames.mjs` 是本轮新增的：按帧号渲染静帧，
用来检查转场与注释在具体某一帧的样子。
