# Scene DSL v2：配方、语义事件、对象身份与导演字段

当前版本号是 **`schema_version = 2`**（v2 新增字段见 §7）。V1/V2/V3 时期写下的脚本仍是
`schema_version = 1`，读取端按字段默认值兼容，可以原样渲染；升级只补版本号，不补造历史证据。
Python 契约在 `src/movelyth/models.py`，渲染端类型在 `studio/src/types.ts`，布局常量在
`src/movelyth/scenedsl.py`，并由 `write_renderer_contracts()` 生成
`studio/src/generated/layout.json` 与 `scene-schema.json`（两侧不会各自漂移，有测试）。

## 1. 新增的镜头字段

| 字段 | 取值 | 默认 | 作用 |
|---|---|---|---|
| `transition` | `cut` / `fade` / `slide` / `wipe` / `dip` / `zoom` | `fade` | 上一镜交接到这一镜的方式 |
| `camera` | `none` / `push` / `pull` / `pan_left` / `pan_right` | `push` | 镜头内的缓慢运镜（幅度 2–4%） |
| `emphasis` | 1–3 个 ≤12 字的词 | `[]` | 重点词；配音放慢+略响，字幕高亮 |
| `cues` | `[{at, kind, gain}]`，≤4 个 | `[]` | 声音提示；`kind` 为 whoosh/tick/impact/riser/chime |
| `chapter` | ≤8 字 | `""` | 章节/段落名，显示在镜号旁 |
| `role` | `hook` / `mechanism` / `example` / `turn` / `conclusion` | `mechanism` | 这一镜在故事里的工作；决定配乐能量、节奏检查与镜像文字 |
| `takeaway` | ≤30 字 | `""` | 这一镜该被记住的一句话，显示在 Insight 卡 |
| `metric` | ≤16 字 | `""` | Insight 卡上的大数字/关键词，必须与画面和旁白一致 |
| `hero` | 图层 id | `""` | 本镜主角；留空时取 `main` 里第一个图形图层 |

图层上另有三个 V3 字段（全部有默认值）：

| 字段 | 取值 | 默认 | 作用 |
|---|---|---|---|
| `annotations` | `[{x, text}]`，≤4 个 | `[]` | 图表的数据注释；`x` 吸附到最近的真实样本，不会画出数据里没有的点 |
| `highlight` | `[x0, x1]` 或 `[]` | `[]` | 图表要强调的 x 区间（越界区、可行区间） |


`at` 与 `actions.start` 使用同一套时间写法（`start` / `end` / 0–1 小数 / `narration:片段`）。

### 转场如何实现

渲染端同时绘制上一镜的最后一帧与这一镜的入场帧：

- `fade`：新镜淡入，旧镜淡出；新镜略快于旧镜消失。
- `slide`：新镜从右侧推入，旧镜同时淡出。
- `wipe`：新镜以**羽化边缘**从左向右揭开，旧镜同步淡出。硬边擦除会让两套版式在接缝处
  互相穿插，看起来像坏掉的幻灯片，因此边缘是渐变遮罩而不是硬切。
- `dip`：两镜之间短暂压黑（`sin` 曲线），用于分段。
- `zoom`：新镜从 1.05 倍轻微推近进入。
- `cut`：硬切，不叠加任何过渡，用于强调或转折。

转场不改变时间轴：它占用新镜开头的 0.4–0.5 秒，旧的画面在这段时间里仍然可见，
因此不会出现"两镜之间闪一下背景"。音频此时本来就有 0.85 s 尾静音 + 0.25 s 前导静音。

### 声音提示

`cues` 由 numpy 本地合成（无采样库、无授权风险），混在配乐层并**跟随人声做侧链压低**，
所以 whoosh 不会盖住句子开头的第一个词。`impact` 每个 cut 最多 2 次（超出会在契约校验被拒）。

V3 起声音**不只由 `cues` 驱动**：`sound.design_sound_events` 从真实动画时间轴生成 Foley——
转场提前 0.24 s 进入（J-cut）、`draw` 起止、`appear`/`scale`/`highlight`、图表“当前点”、
重点词（chime）、结论（chime+sub）、每三句一次翻页声。密度上限 20/min，0.30 s 内的事件合并，
导演写的 `cues` 优先级最高（不会被自动事件顶掉）。全部事件记录在 `timelines.json` 的
`sound_events`，带 `source` 字段便于追责。

## 2. 布局栅格（V3）

V3 把主画面从“右栏一张卡”变成“画面里的主角”，并给左栏一个真正的信息层：

- 横版外边距 96 px：主画面 **1164×730**（V2：1024×660），文字列 520 px。
- 竖版外边距 70 px：主画面 1000×638–714，标题在上、Insight 卡在画面下方。
- 标题 110–112 px（竖版按宽度降到 78–86 px），标签是带语义边的 chip，不再是三根同样的竖线。
- **Insight 卡**是渲染器生成的覆盖层（不在 `regions` 里，旧脚本不会撞上）：它优先用
  `metric`+`takeaway`，否则从真实数据推（图表当前点/最低点/终点、图示节点、时间线步骤、公式右侧），
  每个 coverage beat 换一次。它同时说明“这一句在说哪个数”，也给左栏一个主体。
- 字幕 66 px、两行、下方渐变 scrim；字幕区 900–1012 px（V2：916–1012）。

## 2.1 coverage beat（V3 的讲述节拍）

渲染器按**真实字幕页**把长镜切成 2–4 个 beat：先按 >0.18 s 的页间空隙聚成句子，再按目标
时长分组（>22 s 取 4，>14 s 取 3，>8 s 取 2，否则 1）。每个 beat：

- 换 Insight 卡的主值/标签；
- 换图表注释点（起点 → 最低点 → 关键点 → 终点）；
- 把镜头重新构图（`camera` 的基础上 ±3% 缩放、±1.4% 平移，0.8 s 内完成，末段留稳定期）。

这不是“随机加动画”：beat 的边界来自配音的真实句读，所以画面变化和句子同步。
如果编导给了 `beats`（`at` + `purpose`），优先用编导的锚点。

V2 的 12 列栅格仍保留：`immersive` 是标题在上、主画面占满整宽（V3：1728×444）；
`compare` 是左右（竖版上下）两块；`diagram` 是左文右图。V3 只改尺寸与字阶，不改语义。
标题按区域宽度自动降级（`fitFont` 以 em 宽度估算中英混排）。

## 3. 图表绘制规则

- 刻度用 1-2-5 取整（`0 / 2 / 4 / 6`），不再出现 `0.76 / 2.0 / 3.24` 这种由等分缩放产生的数字。
- 折线/散点连线用**单调三次插值**（Fritsch–Carlson），曲线平滑但不会过冲或凭空造出数据点。
- 常量序列（如"当前点 L=5"）识别为**参考线**（虚线 + 右侧标签）；同一 x 上的多个点识别为
  **标记点**（圆环 + 标签 + 垂线），不再画成一条假的水平数据线。
- 首末值标签带底色块并做垂直避让，不会互相压住；柱子过高时数值移到柱内。
- 图例独立成带，只列真正的数据系列；`source_note` 单独一行。
- x 轴补回刻度（V1 完全没有），柱状图只显示类别位置。
- **V3 数据故事**：单系列图表在主区左上角画图名面板（读者要知道这张图画的是什么）；
  注释点带“数值 + 判断”两行，注释点不再重复画首末值 chip；`highlight` 区间画淡色底 + 两条虚线；
  两柱对比自动画 Δ 括号；`bar` 图不生成自动点注释（柱子自带数值）。
- 字号整体上调约 15–30%（刻度 28、轴标题 28、图例 29、值标 27，均以 viewBox 单位计），
  1920 宽成片里刻度约 32 px，投屏和手机都读得清。

## 4. 字幕与配音

- 配音**按句合成**：每句单独调用 TTS，句间插入按标点决定的停顿（。0.30 s / ？0.36 s /
  ；0.22 s / ，0.15 s），并裁掉引擎在每句首尾加的约 0.2 s + 0.9 s 静音。
  不裁的话，4 分钟片会多出约 45 秒死气。
- 每句可有自己的 `rate` / `pitch` / `volume`：含 `emphasis` 的句子放慢 7%、响 5%，
  问句抬高 2 Hz，首句略慢、末句更慢，长句略快。
- 字幕页携带**词级时间**（来自 TTS 的真实 word boundary），渲染端做卡拉 OK 高亮：
  已读词亮、当前词用 accent 色并带轻底色、未读词降为 48% 不透明度。没有词边界时退化为整页显示。
- V3 配音是**句 → 从句 → 重点短语**三级：从句间 35–100 ms、重点词单独放慢 10%/响 6%、
  末从句略慢；句间停顿仍由标点决定（。0.30 / ？0.36 / ；0.22 / ，0.15）。
  字符偏移保持精确，字幕仍逐字对应。

## 5. 校验边界（新增）

- `emphasis` 的词必须逐字出现在该镜 `narration` 中，否则脚本在审批阶段被拒。
- 同一 cut 的 `impact` 超过 2 次被拒。
- `cues.at` 的 `narration:` 片段同样必须在旁白里出现。
- 节奏是**警告而非拒绝**：镜头时长过于均匀、转场全片一种、没有 cues 也没有自动事件都会写进
  `validation_warnings` 与 `pacing`，交回编导参考，但不阻断一个本身正确的脚本。
- V3：`hero` 必须指向本镜存在的图层（Pydantic 校验拒绝）；`highlight` 必须是两个数；
  `annotations.x` 离最近数据点超过数据跨度 12% 时写警告（会吸附，不阻断）；
  同一图层超过 2 个注释也写警告。

## 6. 兼容性

- 旧脚本（无 `transition`/`camera`/`emphasis`/`cues`）按默认值渲染：`fade` + `push` + 无音效。
- V2 脚本没有 `chapter`/`role`/`takeaway`/`metric`/`hero`：镜号旁只显示序号，Insight 卡退回
  从真实数据推导，主角退回 main 里的第一个图形层。已用 VID-000015 的 timelines 实测渲染。
- 当前 `schema_version` 为 2；v1 脚本按字段默认值兼容，旧 revision 不会被就地改写。
- 布局矩形变了，因此**旧脚本的视觉会变**（更大的画面、更高的标题）。这是本轮的目标，
  不是兼容性回归：语义、图层、时间轴、字幕文本都不变。
## 7. v2：版本化契约、对象身份与语义事件（S1-06）

`schema_version` 升到 **2**。v1 脚本继续可读，但迁移只补版本号，不补造任何历史证据。

| 新增 | 位置 | 约束 |
| --- | --- | --- |
| `schema_version` | Scene / Cut | 1 或 2；高于实现版本直接拒绝 |
| `subject_id` | Layer | 小写标识符；跨镜表示“同一个东西”，与 `layer.id`（本镜实例）分开 |
| `state_before` / `state_after` | Layer | ≤40 字；声明状态必须同时给 `subject_id` |
| `visual_explanation` | Layer | ≤120 字，说明这层画面在解释什么 |
| `claim_ids` | Scene | 只能引用 `c1`、`c2` 这样的主张编号 |
| `hold_reason` / `transition_reason` | Scene | 静止阅读与换场理由，用于解释“为什么不动” |
| `events` | Scene | ≤8 个命名事件；id 同镜唯一 |
| `events_resolved` | 规范化输出 | 每个事件的绝对秒数、0–1 比例、锚点类型与时间来源 |

事件锚点（`EventAnchor`）：

| kind | 字段 | 说明 |
| --- | --- | --- |
| `start` / `end` | — | 镜头首尾 |
| `fraction` | `fraction` 0–1 | 镜头内比例 |
| `narration` | `text` + `occurrence`，或 `char_start`/`char_end` | 绑定到真实配音词语边界 |

校验（`resolve_events`）：

- `narration` 片段找不到第 N 次出现 → 报错，**不会**静默绑定到第一次。
- 事件时间落在镜头外、目标图层/subject 不存在、同一目标的事件倒序、id 重复 → 报错。
- 事件时间来自 TTS 边界时 `timing="tts-word-boundaries"`；只有比例估计时
  `timing="estimated-character-timing"`，不被当成精确时间。

统一时钟（`clock.py`）：

- `seconds_to_frames` 用 1e-4 帧容差向上取整（镜头不能截断自己的音频）；
- `scene_spans()` 给每个镜头半开样本区间 `[start_sample, end_sample)`，相邻镜头首尾相接；
- 全片样本数 = 各镜样本数之和，跨镜不累积漂移。

兼容性：

- v1 脚本（无上述字段）按默认值渲染；`Cut`/`Film` 校验时把场景版本升到 2，仅补版本号。
- v1 版本号下出现 v2 字段会被拒绝（避免“旧版本号悄悄换含义”）。
- 真实渲染 smoke（`pytest -m slow`）用 v1 风格 props 通过，证明旧脚本仍能渲染。
