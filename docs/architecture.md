# 工作流与数据

研究 Agent → 编导 Agent → 独立脚本审稿 → 本地声音/动画制作 → 技术检查 → 实际抽帧审片 → 编号交付。

每个 Agent 是一次独立上下文的 Codex CLI 调用，输出由 Pydantic schema 校验。角色默认串行运行，减少本机资源竞争；这不等同于多个模型供应商的并行集群。模型不生成并执行 shell，也不修改制作工程；画面只采用枚举支持的组件及有界参数。

## 来源与适用范围

研究角色可使用只读搜索，记录支持具体主张的来源；审稿角色核查脚本与来源的对应关系。机器检查和 AI 审稿不能替代所有领域的人工事实审查。首版适合能用现有程序动画表达的数学/科学概念；完整科研结果复现、任意剧情/人物视频不是已验证能力。

来源只作为文本引用。本版图像为自身程序绘制，SVD 数据由 NumPy 真实计算；不自动下载并转载第三方图片或视频。

## 台账

`workspace/studio.sqlite` 使用 WAL 与事务分配编号。`episodes` 保留标题意图、状态、运行进程、错误和交付路径；`events` 追加阶段起止与失败；`ideas` 保留未来选题；`feedback` 保存带观察时间的数据；`publications` 将发布状态与制作 ready 分开记录。

相同规范化标题默认恢复原任务；`--new` 表示另做一个新任务，获得新编号。它不是原作品的原地覆盖修订。标题规范化仅能处理完全相同/标点不同的标题，语义去重还需要选题角色或用户判断，尚无向量库相似度保证。

运行锁由数据库事务和进程存活检查维护。强行结束进程后可重新认领；PID 被系统重用的少见情形可能需要人工确认，程序不会直接终止别人的任务。

## 缓存与文件

每个阶段保存输入 hash、输出文件 hash 和结果。输入变化、缓存损坏或缺文件时重新执行；不只凭文件存在认定成功。语音缓存以文本、音色、语速与实现版本为 key，保留真实边界时间和 PCM 音频。

已通过校验的研究与脚本在同一任务恢复时保持固定，避免修复渲染器却重写故事并重新合成所有语音；复用仍检查原始产物 hash 并记录原始/当前输入版本。prompt 更新默认用于新任务，明确重做用 `--new`。实际审片反馈要求改写时会解除脚本冻结；导入新脚本也会重新审核。

研究/编导/审稿的 prompt、schema、原始结构化结果与事件日志保存在对应任务的 `agents/`。它们属于本地运行数据，不提交 Git。无效的模型内容不会作为可执行代码处理。

## 声画

先按镜头合成 Edge TTS，再按音频真实样本数对齐帧数。字幕优先使用语音边界；匹配不到时标明估计时间模式。程序配乐按真实旁白能量降低音量，FFmpeg 混音、响度归一化并编码 AAC。Remotion 生成 1920×1080 横版和 1080×1920 的独立短版场景序列。

视觉素材：矩阵、向量、投影、波形、网络、低秩图像和三维点云。动画只依赖 frame/props，无实时 CSS 动画和随机外部状态。

## 检查和交付

检查实际最终文件的完整解码、H.264/AAC、画幅、帧率、时长、音量、黑屏与低分辨率时间采样运动变化；再把每镜代表帧交给独立视觉审片。抽帧审片不能证明全片运动观感，音量检查不能证明配音听感或术语全部正确，本版未内置 ASR/人工实听。

脚本或视觉审片拒绝不会进入待上传。编导对脚本问题最多修复两次；视觉问题会把实际抽帧反馈交回编导，最多重做两轮。模型只能修改结构化内容，不能自动改渲染代码。达到次数上限或遇到程序故障时留下 failed；程序故障可在修复后恢复，但不表示任意语义/审美问题都能自动解决。

交付先写 `.staging`，hash 核验后重命名至 `待上传`，最后更新数据库。已存在且损坏的交付包不会被覆盖。`manifest.json` 证明具体文件版本，`质检报告.json` 记录检查与限制，`发布文案.md` 含标题、标签、说明与来源。
