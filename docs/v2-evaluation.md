# V2 对照评估：同一脚本，换一套渲染与声音

日期：2026-10-27。对象：`main` + 本轮改动（未提交前的工作树）。

## 0. 结论

- 视觉层（构图、图表、转场、字幕）完成结构性改造，**同一份已审脚本**重渲染后画面明显更接近
  专业讲解片：标题 92 px 起、标签紧跟标题、图表刻度取整、曲线平滑、转场有五类且旧画面不再提前消失、
  字幕逐词高亮。
- 声音层完成从"念稿"到"按句讲解"的改造：句级韵律、真实句间停顿、三段式配乐、带 lookahead 的
  侧链、与画面同源的音效。机器指标全部通过（响度 -14.3 LUFS、真峰值 -1.1 dBTP、
  混音/原声最大比 1.196）。
- **未完成**：真实 Codex 编导（本机无 `codex`）；人工观看与实听。这两项在后文单独标注，
  不用机器指标冒充。

## 1. 实验设计

本机没有 Codex CLI，无法用新 prompt 重新生成脚本。因此采用**受控对照**：

| | V1（对照） | V2（本轮） |
|---|---|---|
| 任务 | `VID-000004` | `VID-000015` |
| 脚本 | 已审 `film.json` | **同一份**，仅做两处机械修复（见下） |
| 配音文本 | 逐字相同 | 逐字相同 |
| 研究 | 相同 | 相同 |
| 渲染 | V1 渲染器 | V2 渲染器（栅格/图表/转场/字幕） |
| 声音 | 整段 TTS + 8 s 循环正弦和声 | 句级 TTS + 三段式配乐 + 音效 + 侧链 |
| 审片 | 真实 Codex | **mock 预设**（无 codex，报告已标 `provider: mock`） |

对脚本的两处机械修复（不改文字、不改图层类型、不改时长）：

1. `l2` 图示的两个节点重叠 65 单位（今天的关系式校验会拒绝，V1 交付时该规则还没加），
   把三个节点改成品字形。
2. 补齐 V2 字段的默认方向（`transition` 按段落轮换、`camera` 轮换、每镜一个 `whoosh`/`impact`），
   脚本 `workspace/ab/make_film.py` 可复现。

**这不是"V2 比以前聪明"，而是"同一份脚本，V2 做得更好看、更好听"。** 脚本层面的节奏问题
（九个镜头 24.5–28.2 s）仍然存在，见 §5。

## 4. 声音：能测的与不能测的

**能测**（`quality.json` → `sound_design` / `audio`）：

- 语音按句合成（`prosody: "sentence"`），218 段句间停顿，停顿长度由标点决定
  （。0.30 s / ？0.36 s / ；0.22 s / ，0.15 s）。
- 配乐 RMS -30.5 dBFS，动态范围 20.3 dB；人声出现时侧链压到约 -11 dB 的增益（floor 0.26）。
- 音效密度 2.33/min，1 次 impact（开场）+ 8 次 whoosh（每次转场），全部落在大约
  场景边界前 0.25 s，并在人声起音时被侧链压低。
- 没有长静音（`silence: ok`），没有削波，响度对齐平台。

**不能测**（必须人工）：音色是否自然、停顿是否在"气口"上、配乐是否好听、
音效是否刺耳、重点句放慢是否被听出来。报告里 `listened_by_human: false`。

我也**没有实听**：作为自动化流程我只能测信号与统计，不能替代人的耳朵。这一点必须明确，
否则就是把"指标通过"写成"声音好"。

## 5. 仍然不够好的地方（按影响排序）

1. **节奏仍然均匀**：九个镜头 24.5–28.2 s（`uniform_shots: 9`）。这是脚本层面的问题，
   渲染器改不了。V2 的 prompt 已要求"铺垫镜 8–14 s、机制镜 18–28 s、结论镜 10–16 s"，
   并把这个指标写进 `pacing` 报告与审片上下文，但**没有真实模型跑过，效果未验证**。
2. **三镜一循环的布局**：`repeated_visual_signatures` 显示两个镜头是 `chart:line|text:line`。
   视觉签名校验只要求"至少三种"，没有惩罚重复，后续可以按 cut 统计重复率并给警告。
3. **图表仍是"一根曲线 + 两个标签"**：缺少注释箭头/区间高亮。这需要新的图层类型或
   更丰富的 chart 参数（P1，未做）。
4. **音效只有 whoosh/impact 被用到**：`tick`/`riser`/`chime` 已实现并测试，但这份脚本
   没有写这些 cue。需要模型在新脚本里使用。
5. **未做真实端到端**：没有 Codex 就无法验证新 prompt 会不会被模型正确执行、会不会因为
   新增必填字段而更容易触发修复循环。
6. **转场只有 0.4–0.5 s 的固定时长**：没有按镜头内容（比如同一物体的匹配剪辑）自适应。

## 6. 下一步建议

1. 在有 Codex 的机器上跑 2 个新题材，验证 prompt 里 `transition`/`camera`/`emphasis`/`cues`
   的采纳率与 `pacing` 警告是否下降。
2. 人工完整观看 V1/V2 两版并实听，按"叙事清晰/画面贴合/声音自然/字幕可读/愿意看完"打分，
   把具体时间点写回 `docs/v2-evaluation.md`。
3. 如果节奏仍均匀，把 `pacing` 从警告升级为"编导必须给出解释"的显式字段，
   而不是继续加特效。
4. 单镜重渲染（P1-5）仍是提升迭代速度的最大工程项。
